EAMS-SRS-2026 · System Flow Summary

E-Asset Management System — How the System Flows End-to-End

A structured walk-through of the complete E-AMS platform: from first login to AI-generated insight, covering every module, data layer, and integration point.

01 — Master Flow

The Big Picture: How the System Works

Every interaction in E-AMS follows a consistent pattern: an actor authenticates → performs an action → the action is validated by RBAC → the database is updated → the audit log is written → notifications/AI are triggered. The pipeline below shows this top-level flow.

01 Identity & Auth SSO / MFA login, AD/LDAP sync, session scoped by role
02 RBAC Check Permission evaluated per asset category & location
03 Asset Action Register / edit / check-out / grant access / change config
04 Workflow Engine Multi-step approval, SoD enforcement, escalation routing
05 DB Commit Record saved, computed fields updated, relationships linked
06 Audit Log Immutable HMAC-signed entry written for every change
07 Notifications Email / SMS / in-app alerts + webhook to Teams/Slack
08 AI Layer Predictions updated, anomalies scanned, recommendations refreshed
02 — Setup & Onboarding Flow

Before Anything Else: Organisation Setup

A new tenant's journey starts in the Administration Console. No code changes are ever needed — all configuration is data-driven.

STEP 1 · FR-SY

Provision Tenant

  • Create organisation record (name, slug, timezone, locale, country)
  • Upload logo, set primary colour for white-label branding
  • Set subscription plan and max asset limit
STEP 2 · FR-SY

Define Location Hierarchy

  • Create hierarchy levels: Country → Region → Branch → Building → Floor → Room → Rack
  • Assign GPS coordinates and contact emails per branch
  • Level names are configurable (e.g. Division / District / Site)
STEP 3 · FR-SY

Configure Asset Categories

  • Activate the 6 default categories (Apps, DBs, Servers, Network, Client Devices, Certs)
  • Define Asset ID format templates per category (e.g. APP-NBI-2026-0042)
  • Add custom fields without schema changes
STEP 4 · FR-UM

Import Users & Set Roles

  • Sync users from Active Directory / LDAP
  • Configure SAML 2.0 / OIDC for SSO
  • Assign RBAC roles; second admin approval required
  • Set MFA requirement per role
STEP 5 · FR-SY

Configure Workflows & Notifications

  • Design approval workflows in the Workflow Designer
  • Set notification rules (expiry intervals, escalation paths)
  • Configure SMTP, SMS gateway, and webhooks
STEP 6 · FR-AR

Bulk Import Existing Assets

  • Upload CSV / Excel with field mapping wizard
  • System validates, detects duplicates, then commits
  • Every imported record creates an audit log entry
03 — Day-to-Day Operations

Core Module Flows in Normal Operations

FR-AR · Asset Registry

Asset Lifecycle

  • Staff registers new asset → mandatory fields enforced → Asset ID auto-generated
  • Asset links to location, department, owners, and related assets (CMDB)
  • Status flows: In Procurement → In Stock → In Service → In Maintenance → Decommissioned
  • Every field edit is captured in the immutable audit log
  • QR/barcode generated for physical labelling and scanning
FR-CO · Check-In / Check-Out

Asset Assignment

  • Staff submits check-out request via self-service portal
  • Authorising officer approves → asset assigned to user/department
  • System tracks expected return date; auto-alerts at 7d and 1d prior
  • Overdue assets flagged and escalated to Asset Manager
  • Inter-location transfers require two-step acknowledgement
  • Full assignment history kept from registration to present
FR-CL · Certificates & Licences

Expiry Management

  • Daily job calculates days_remaining for every cert and licence
  • Status bands auto-applied: VALID → REVIEW SOON → WARNING → CRITICAL → EXPIRED
  • Multi-channel alerts sent at 180, 90, 30, 14, 7, 1 day before expiry
  • Renewal workflow auto-triggered at configured lead time
  • Licence seat utilisation tracked in real time; alert at 85% threshold
  • Full certificate version/renewal history maintained
FR-AC · Access & Change Control

Privileged Access & Changes

  • Temporary access grant raised with mandatory business justification
  • Approver (different from requestor) authorises with expiry timestamp
  • System auto-flags expired grants not revoked within 1 hour
  • Config changes follow: Proposed → Approved → Applied → Pending Revert → Reverted
  • Mandatory scheduled revert date on every change; overdue state escalates automatically
  • Proposer and approver enforced to be different users at the engine level
FR-UM · People Management

User Lifecycle

  • Users synced from AD/LDAP; no manual duplication needed
  • Contractors get mandatory expiry dates; auto-revoked on expiry
  • On termination: off-boarding checklist triggered, all assets must be returned within 24h
  • "View as user" report shows every asset and access right for audit reviews
  • Role changes require second-admin approval; no self-escalation possible
FR-AU · Audit & Compliance

Audit Trail

  • Every action (create/read/update/delete/export/approve/login) written to audit_logs
  • Each entry HMAC-SHA256 signed for tamper detection
  • Retained minimum 7 years; auto-archived after year 1
  • Searchable by date, user, action type, asset category, record ID
  • Evidence packages exportable as PDF for external auditors
  • SIEM forwarding in CEF/JSON (Splunk, Sentinel, QRadar)
04 — AI Intelligence Layer

How the AI Module Operates

The AI layer is a modular, provider-agnostic engine. Models are registered in the ai_models registry, must be approved before production use, and can be swapped without code changes. Six capability domains run continuously.

Predictive Analytics

Failure & Lifecycle Risk

Inputs: asset age, warranty status, patch dates, vendor EOS dates. Outputs: risk score + probability written to ai_predictions. Displayed on executive dashboard.

Anomaly Detection

Unusual Audit Patterns

Streams the audit log in near-real-time. Flags bulk exports at odd hours, mass deletions, privilege escalations. Writes to ai_anomalies and surfaces in Audit Module dashboard.

Recommendation Engine

Cost & Risk Optimisation

Analyses utilisation, costs, lifecycle. Generates prioritised recommendations (consolidate licences, decommission, patch now) with estimated savings. Stored in ai_recommendations.

Natural Language Interface

Plain-English Asset Queries

Users type questions like "Which servers haven't been patched in 90 days?" — system translates to structured queries and returns results. Sessions stored in ai_chat_sessions.

Report Narration

Auto-Generated Summaries

When any standard report is generated, AI writes a plain-English executive summary highlighting key findings, trends, and required actions. Embedded directly in the report output.

Budget Forecasting

12–36 Month Projections

Uses historical spend + upcoming warranty/licence expiry data to project IT budget requirements. Confidence intervals provided. Stored in ai_predictions.

🔒 AI Governance Rules Built Into the System

No PII is sent to external AI providers — data is pseudonymised by default. Every AI model must be explicitly approved by an admin before production use. All AI outputs carry a confidence score and are presented as recommendations, never automated decisions. A human-in-the-loop feedback mechanism captures false positives and feeds back into model accuracy over time. Every AI-generated insight is written to the audit trail for full traceability.

Key Architectural Principles

Multi-tenancy: Every table has an organisation_id column — all queries are automatically scoped to the tenant. Complete data isolation at the database level.

Configure, don't code: Asset categories, field schemas, workflow steps, notification rules, AI thresholds, role names, and branding are all controlled through the Admin Console. No redeployments needed.

Horizontal scalability: Application nodes sit behind a load balancer. Adding nodes requires no architectural changes. AI prediction batch jobs run in off-peak windows to avoid degrading interactive sessions.

99.5% availability: Active-passive HA with ≤15 min RTO. Full daily DB backup + transaction log every 15 minutes (RPO ≤ 15 min). Quarterly restore tests logged in the audit trail.
